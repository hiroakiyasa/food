# Repository Guidelines

## Project Structure & Module Organization
This repo contains a mobile/web Expo app plus a data ingestion workspace.

- `app/`: Expo Router screens and layouts (`(tabs)`, `(modals)`, `auth/`).
- `src/`: application logic (`hooks/`, `services/`, `stores/`, `lib/`, `types/`, `utils/`, `components/`).
- `components/`: shared UI primitives and legacy snapshot test files.
- `scraper/`: separate Node + TypeScript workspace for food dataset pipelines (MEXT + USDA).
- `data/`: large raw/extracted/output JSON files generated by scrapers.
- `assets/`: fonts/images used by Expo.
- `supabase/`: project scaffolding for migrations/functions.

## Build, Test, and Development Commands
- `npm install`: install root dependencies.
- `npm start`: run Expo dev server.
- `npm run ios` / `npm run android` / `npm run web`: launch platform-specific dev targets.
- `npx tsc --noEmit`: strict type-check for app code.
- `npm run --prefix scraper usda:test`: run USDA scraper in test mode (small sample).
- `npm run --prefix scraper usda:download`: download USDA datasets without full conversion.

## Coding Style & Naming Conventions
- Use TypeScript with strict typing; avoid `any` unless justified.
- Use 2-space indentation, semicolons, and keep import ordering clean.
- Follow local file style for quotes and import paths; do not reformat unrelated files.
- Name hooks as `useXxx` (`src/hooks/useMeals.ts`), stores as `xxxStore.ts`, and route files by feature (`app/(modals)/meal-detail.tsx`).
- Prefer alias imports (`@/...`) in app code where configured.

## Testing Guidelines
- Current automated tests are minimal (`components/__tests__/StyledText-test.js`).
- Test files follow `*-test.js` in `__tests__/`.
- No coverage gate is configured; for now, require at least:
  - `npx tsc --noEmit` for app changes.
  - `npm run --prefix scraper usda:test` for scraper/data pipeline changes.

## Commit & Pull Request Guidelines
- Existing history is minimal (`Initial commit`), so use clear imperative commit titles (example: `Add meal insight chart state handling`).
- Keep commits focused by area (app UI, scraper logic, data updates).
- PRs should include: summary, affected paths, validation steps run, and screenshots for UI changes.
- Link related issues/tasks and call out any large `data/` file regeneration.

## Security & Configuration Tips
- Never commit secrets or service-role keys.
- Treat `src/lib/constants.ts` as non-secret client config only; move new sensitive values to environment-based configuration.
