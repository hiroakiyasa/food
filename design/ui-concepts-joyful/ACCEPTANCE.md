# UI Acceptance Criteria

## 全画面共通

- [ ] 対象PNGの情報階層、配色、明るい雰囲気が再現されている
- [ ] 正式タブ名とrouteが統一されている
- [ ] 画像を背景や切り抜き素材として使用していない
- [ ] サンプル値をハードコードしていない
- [ ] 既存のhooks、stores、servicesから実データを受け取る
- [ ] loading、empty、error、offlineを扱う
- [ ] Premium制限のある機能は既存の購入導線を維持する
- [ ] 44pt以上のタップ領域がある
- [ ] VoiceOverのlabel、role、stateが設定されている
- [ ] 文字拡大時に重要操作が欠けない
- [ ] コントラストが十分で、色だけに意味を依存しない
- [ ] iPhone SE相当の幅で横スクロールや切れがない
- [ ] AndroidのSafe Areaと戻る操作が成立する
- [ ] `npx tsc --noEmit` が成功する

## コアループ

- [ ] ホームからカメラ、検索、AI入力へ到達できる
- [ ] 記録後に食事一覧と日次集計が更新される
- [ ] 食事詳細から編集・削除・栄養バランスへ移動できる
- [ ] カメラ権限拒否、解析失敗、再撮影を扱う
- [ ] 食品検索で分量変更と複数品目追加ができる
- [ ] AI会話の解析途中・失敗・修正・保存を扱う

## 健康情報

- [ ] 診断や治療を断定しない
- [ ] HealthKit/Health Connectの未接続・権限拒否を扱う
- [ ] 月経周期、疾患、健診情報のプライバシー説明がある
- [ ] 危険値は楽しい装飾より明瞭な説明を優先する

## Visual QA

- [ ] 対象PNGと実装スクリーンショットを並べて比較した
- [ ] 上部の第一情報、主ボタン、下部ナビの視線順が一致する
- [ ] カード角丸、余白、影、見出しサイズが共通トークンに従う
- [ ] 食事写真のcropと比率が統一されている
- [ ] 達成装飾が過剰でない
